## 三、核心实现策略（已留痕）

- `# DECISION(§8.4 补丁幂等)`：补丁统一 `unren-*.rpy` 命名；`apply_patch` 对已存在文件**拒绝覆盖**（抛 `GameError`，引导先 `remove_patches`），满足「可卸载 + 幂等」；
- `# DECISION(§8.5 回退)`：`SdkBridgeImpl.generate` 在无本机真实 SDK 时（launcher 不可执行或调用失败）**安全回退** `_builtin_skeleton`，不抛未捕获异常，保证 CI 零外部依赖通过；
- `# DECISION(§15.2 回滚)`：写回以文件为粒度记 `backup` 路径，rollback 逆序还原（有备份则 copy2 还原，新建文件则删除），与 `JsonWriteJournal` 契约一致。

## 四、偏差与决策（deviation notes）

1. **unrpyc 采用薄封装 + drop-in 真实上游（ADR-0008）**：真实上游 unrpyc 体量庞大不在 W4 范围；`vendor/unrpyc.py` 处理合成 `fake_game` 的 `.rpyc` 使 29 项测试零外部依赖全绿，并预留 `vendor/unrpyc_real/` 目录供后续 drop-in。真实游戏的完整反编译覆盖率取决于用户是否放置真实上游（见 §15.5 第 3 点）。
2. **`tests/conftest.py` 沙箱 basetemp 回退（任务级取舍）**：仓库默认 `addopts` 含 `--basetemp=.pytest_tmp`，而该目录残留早期失败运行留下的 `pip-*` 锁定子目录（0o700，沙箱附加 `Deny` 扫描 ACE），pytest 会话启动 `rm_rf` 与收尾 `cleanup_dead_symlinks` 在标准 basetemp 上 `PermissionError`。已在 conftest 的 `TempPathFactory._getbasetemp` 打补丁：当给定 basetemp 无法清理时，用 `os.mkdir(path, 0o777)`（**不可**用 `tempfile.mkdtemp`——其强制 0o700 会再次触发沙箱锁）在系统临时树下新建可扫描回退目录并 `resolve()` 后返回。该改动仅作用于测试脚手架，不触及任何 W4 交付契约。
3. **四类辅助补丁默认不随「全部」自动执行**：与设计 §8.4 一致，补丁须在游戏目录页独立勾选，且可一键移除；本交付提供程序化注入/卸载能力，UI 勾选交由 W5。

### 8.2 核心约束与架构结论（ADR-0008 关闭）

- 真实上游在模块加载时 `import renpy.object`，**不能**在项目解释器（3.10/3.13，

- 「存在性检测」为**目录检测**（非 import）；真实解码路径经 `subprocess` 到
  `vendor.unrpyc_real.runner`，每进程一次 `import renpy`。

### 8.3 8.3.7 兼容性适配（§0.5 偏差）

上游 2019 版针对 Ren'Py 7.x；对 8.3.7 做三处最小补丁（保留上游功能）：

1. `unrpyc.py` `PyCode.__setstate__`：兼容 4-/5-tuple co 状态。
2. `decompiler/__init__.py`：对缺失 `hide` 属性的 AST 节点 `getattr` 守卫。
3. `decompiler/magic.py` `FakePackageLoader`：PEP 302 `find_module`/`load_module`

> **偏差（§0.5）**：上游 2019 版对**部分** Ren'Py 8.3.7 的 `.rpyc` 节点

### 9.1 修订动因（旧 44febb0 在 Ren'Py 8.3.7 上三处已确认缺陷）

| # | 旧 `44febb0`（Ren'Py 7.x 时代）缺陷 | v2.0.4 |
|---|---|---|
| 1 | `read_ast_from_file()` 把整个 slot **字典**喂给 `zlib`，表现 `TypeError: a bytes-like object is required, not 'dict'` 或用户实际看到的 `Error -5 ... incomplete or truncated stream` | 显式取 `chunks[1]`；异常改为有类型的 `BadRpycException` |

### 9.2 上游版本与来源（真实、可审计）

### 9.3 架构变化：子进程桥不再是必需项（ADR-0008 关键修订）

v2 **不再 import 真实 `renpy` 引擎**：`decompiler/renpycompat.py` 经 `magic.fake_package("renpy")` 自建伪 `renpy` 包，并用自己的兼容类从 pickle 流重建 AST。因此：

- `decompile_file()` 可**直接在本项目解释器内运行**（仅要求 Python ≥ 3.9），不再需要 §8.5 的子进程桥与真实 Ren'Py SDK/解释器；
- `_decompile_in_process()` 成为默认路径；**仅当调用方显式传 `python_exe=`**（如用游戏自带解释器）时才走子进程，此时仍须 `sdk_root=`；
- `runner.py` 的 `--sdk-root` 由必填改选填，仅为兼容性保留；
- 该变化消除了「游戏自带解释器 + 引擎路径」部署耦合：旧版探测失败（或沙箱禁写 temp）即整链失败，如今不依赖外部解释器。
