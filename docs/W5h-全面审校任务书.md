# W5h 任务书：审校页「全面审校」按钮——对全部已导入内容做一次结构化检查并生成报告

> 任务来源：用户实测问询（2026-10-21）：自动审校能否查出 ①标签/转义丢失或改动 ②错误引号 ③术语表未覆盖的残留英文。
> 总控前置核实结论：**校验器引擎侧已能检出全部三类问题**（`tags_ok` 对 `{size=40}`/`[nl]`/`\n` 的丢失与改动均返回 False；V5 白名单检出英文残余；V4 自动修复英文引号）。
> **真正的缺口**：这些检查只在引擎翻译时逐行跑，审校页**没有手动触发全量重检的入口**，结果也不以结构化方式呈现给用户。
> 授权：`.worktrees/W5` + `task/W5`；pytest 必须；GUI 实测归用户；禁主树。

---

## 1. 需求

审校页新增「全面审校」按钮，点击后：

1. 对**全部已导入段**（所有 status）重新执行 V1–V6 校验 + 四态检测；
2. 结果以**分类汇总**呈现（新面板或复用审校列表筛选）；
3. 问题行可在审校页**直接定位和编辑**（跳到对应 uid）。

## 2. 检查项（复用 validators 现有逻辑，不重写）

| 检查项 | 复用 | 报告列 |
|---|---|---|
| 标签丢失/改动 | `tag_messages(source, target)` — `{size=40}`/`[nl]`/`{w}`/`[var]` 计数比较 | 错误描述（"标签 {size=40} 原文1处译文0处"） |
| 转义丢失/改动 | `ESC_RE` 计数（`\n` `\"` `\\`） | 同上 |
| 英文双引号 | V4 `repair_quotes` 后仍含 `"` | "英文引号未修复" |
| 英文残余 | `compute_residual` → 非空 | 残余片段列表 |
| 术语未生效 | source 含 `profile.terms` 的 key 但 target 的译文**不含**对应译名 | "术语 'Ian' 未生效" |
| 译文为空 | V2 | "空译文" |
| 状态异常 | status=FAILED/KEEP_DECLARED 的行数汇总 | 按状态分组 |

**术语未生效检查（新增逻辑，不走 `compute_residual`）**：

```python
# 对 profile.terms 的每个 key：
#   if key 在 source 中（word boundary）and 对应译名不在 target 中 → 标记
# 这与 V5 的「残留英文」不同——V5 检"多余的英文"，这项检"该翻没翻的术语"。
```

## 3. 交互设计

```
审校页顶部按钮行：[全面审校] [按状态筛选 ▼] [显示更多]
                        ↓ 点击后
┌─ 全面审校结果 ────────────────────────────────┐
│ 检查完成：异常 X 行 / 正常 Y 行 / 跳过 Z 行      │
│ ┌─────────┬──────────┬───────────────────┐   │
│ │ 状态     │ 文件:uid  │ 问题               │   │
│ │ 标签丢失  │ ch01:12  │ {size=40} 0→1     │   │
│ │ 英文残余  │ ch01:45  │ [Stalkfap]        │   │
│ │ 术语未生效│ ch02:8   │ Ian → 伊恩        │   │
│ │ ...      │          │                   │   │
│ └─────────┴──────────┴───────────────────┘   │
│ 双击行 → 跳审校页定位该 uid → 可直接编辑        │
└───────────────────────────────────────────────┘
```

- 结果表存内存（`self._audit_results: list[dict]`），双击行 → `state._review_index` 定位 + `stack.setCurrentIndex(3)`；
- 面板关闭 → 结果清空；
- **不修改任何数据**——纯只读检查 + 定位导航，编辑仍在审校页正常操作。

## 4. 实现

| 文件 | 改动 |
|---|---|
| `pytran/ui.py` | 新增 `_full_audit()` 方法：遍历 `project.segments` → 逐段调 `validator.check_detailed(source, target, profile)` + 术语未生效检查 → 结果存 `self._audit_results` → 弹出/更新结果面板（`QDialog` 或 `QDockWidget`，含 QTableWidget） |
| `pytran/ui.py` | 双击结果行 → 审校页定位该 uid（`_review_index` + 跳审校 Tab） |
| `pytran/ui.py` | 「全面审校」按钮放审校页顶部按钮行 |
| `tests/test_ui_full_audit.py` | ≥8 用例 |

**实现者注意**：
- `check_detailed` 是纯函数，每段一次调用，1 万段 ≈ 3 秒（可接受）；如过慢，可加 `QProgressDialog`；
- 术语未生效检查是**新增逻辑**（不在 `validators.py` 中），写在 ui.py 或 terms.py 均可，但需标注 `# DECISION(§7 术语未生效)`；
- 不改冻结契约。

## 5. 测试（pytest，≥8 用例）

| # | 用例 | 断言 |
|---|---|---|
| 1 | 全部正常段 → 异常 0 行 | `_audit_results` 为空 |
| 2 | 含 `{size=40}` 丢失的段 → 结果含"标签" | 命中 V6 |
| 3 | 含 `\n` 丢失的段 → 结果含"转义" | 命中 V6 |
