## A 级：功能缺陷

### A1. 设置对话框「保存」在「译名为空」分支必崩 —— `re` 未导入

**现象**
在「⚙ 设置 → 术语表」中，只要表格里存在**原文非空、译名为空**的行，点「保存」立即抛 `NameError: name 're' is not defined`，对话框不关闭、任何设置都不落盘。

**代码定位**
`pytran/ui.py:648`

```python
def save():
    ...
    for row in range(table.rowCount()):
        ...
        if dst:
            terms_map[src] = dst
        elif re.search(r"[A-Za-z]", src):   # ← 648 行，re 无绑定
            exempt_add.append(src)
```

**根因**
`re` 在 `pytran/ui.py` 中**从未导入**。已做四重确认：

1. 全文 `import re` 出现次数 = **0**（模块级 / 类级 / 函数级均无）；
2. `import pytran.ui; hasattr(module, "re")` → `False`；
3. `re` 不是 builtin，模块级也无 `re = ...` 赋值；
4. **决定性复现**：把 `save()` 函数体（`ui.py:631-664`）原样抽出，仅 stub 其依赖的 Qt 对象后执行：

```
RESULT: NameError -> name 're' is not defined
```

**为什么测试全绿却没人发现**
- `_open_settings` 整体位于 `run()` 内，`run()` 标注 `# pragma: no cover`；
- `tests/test_ui_settings.py` 的 12 个用例全部只调用 `_apply_settings` / `_coerce_setting` / `_validate_sdk`，**没有任何测试调用 `_open_settings`**（grep 全 tests 目录 0 命中）；
- GUI 的 `save()` 也从不调用 `_apply_settings`（见 A3）——即测试覆盖的路径与 GUI 真实路径是两条。

**复现步骤**
1. `运行.bat` 启动 GUI；
2. 点「⚙ 设置」→ 切到「术语表」页；
3. 点「添加行」，在「原文」列填 `Stalkfap`，**「译名」列留空**；
4. 点「保存」→ 崩溃。

> 注意：W5b 任务书 §3.2 的示例表格里 `Stalkfap` 一行正是「译名留空 = 按原文保留」，即**按设计文档教用户的操作必崩**。
> 若每行都填了译名，`if dst:` 先命中，`elif re.search(...)` 不执行，则不崩——这解释了为何部分操作路径下"看起来正常"。

### A2. 新增的 3 个数值字段在设置里退化为字符串

**现象**
在设置里改「请求超时秒」「重译轮上限」「前文参考行数」后，**当次会话**内这些值是字符串，可能导致翻译启动即崩或参数被静默传错。

**代码定位**
`pytran/ui.py:162-180`（`_coerce_setting`）与 `pytran/ui.py:192-194`（留空白名单）

`_coerce_setting` 的类型分支只覆盖：

| 字段 | 收敛类型 | 状态 |
|---|---|---|
| `max_tokens` / `max_workers` / `round_budget_cap` | `int` | ✅ |
| `temperature` / `top_p` | `float` | ✅ |
| `timeout` | — | ❌ 按字符串 |
| `max_retry_rounds` | — | ❌ 按字符串 |
| `context_lines` | — | ❌ 按字符串 |

而这 3 个字段在设置 Tab1（`ui.py:540-554`）里都存在（`44bbf65` 新增）。

**根因**
`44bbf65` 给对话框加了 8 个字段，但只扩了 `Config`/`segmenter`/`engine` 的接收侧，没同步 `_coerce_setting` 的类型表，`_apply_settings` 的「数值留空保留既有值」白名单也没扩。

**会造成什么**

第一层（直接崩）：
- `_coerce_setting("max_retry_rounds", "3")` → `"3"`；
- `Config.effective_max_retry_rounds()` 执行 `min("3", 5)` → `TypeError: '<' not supported between instances of 'str' and 'int'`；
- 留空白名单不含这 3 个字段 → 用户清空 `timeout` 会把超时写成空串。

第二层（被 `Config.load` 掩盖，重启后自愈）：
`pytran/config.py:135-146` 的 `_coerce_types()` 会在读盘时把字符串转回数字。因此：
- **当次会话**：`cfg.timeout == "120"`（str）、`cfg.context_lines == "3"`（str），分别传给 openai SDK 的 `timeout` 与 `Segmenter(context_lines=)`；
- **重启 GUI**：从 ini 重新 load，类型恢复正常。

净效果是「改完设置，这次翻译用着坏参数，重启就好」——最不易被发现的一类缺陷。

**复现步骤**
1. 设置 → 常规 → 把「请求超时秒」改成 `60`，「重译轮上限」改成 `2` → 保存；
2. **不重启**，直接回翻译页点「开始自动翻译」；
3. 观察是否报错 / 参数是否生效（预期：`max_retry_rounds` 触发 `TypeError`，或参数被静默传错）。

### A3. 设置保存绕过 `_apply_settings`，测试覆盖的是 GUI 不走的路

**现象**
设置对话框的「保存」与 `tests/test_ui_settings.py` 验证的逻辑**不是同一套代码**。

**代码定位**
`pytran/ui.py:631-634`

```python
def save():
    for attr, e in entries.items():
        setattr(cfg, attr, e.text().strip())   # 全部按字符串 setattr
    cfg.save(self.work_dir)                    # 直接落盘
```

**根因**
`save()` 未调用 `_coerce_setting`，也未调用 `_apply_settings`（`ui.py:182-196`）。后果：
- 13 个字段（含 `max_tokens`、`temperature`）**全部以字符串**写入内存 `cfg` 再 `cfg.save()`；
- `Config.save` 走 `_INI_SECTION_MAP` 逐项 `str()` 写 ini，所以 **ini 文件内容看起来正常**、重启后也正常；
- 但当次会话的 `cfg` 对象里数值字段全是字符串（与 A2 叠加，A2 的三个字段 100% 中招）。

**待用户确认**
此项与你的"亲测没有问题"存在冲突，需要区分实测口径：
- 若验证的是「保存后 `config.ini` 内容正确」或「重启后行为正确」→ 确实无问题（ini 落盘路径不依赖内存类型）；
- 若验证的是「不重启、改完立刻影响下一次翻译」→ 理论上 `config.temperature` 是字符串 `"0.5"`，会原样进入 openai 请求参数。

### A4. §9 工具区「辅助补丁 + 移除补丁」整块缺失

**现象**
设计 §9 布局图要求的工具区 `[辅助补丁□控制台□快存□跳过□回滚] [移除补丁]` 在 GUI 中**完全不存在**。

**代码定位**
`pytran/unren.py:258-290` 的 `apply_patch` / `remove_patches` / `_PATCH_TEMPLATES` **已完整实现**（含 §8.4 的幂等拒绝覆盖、统一 `unren-*.rpy` 命名、一键卸载）；但 `pytran/ui.py` 中 `apply_patch` / `remove_patches` / `unren-` **grep 零命中**。

**根因**
W4 交付说明第 75 行原话：「四类辅助补丁默认不随『全部』自动执行…**UI 勾选交由 W5**」。W5 未交付，至今悬空——实现完毕但无入口。

**设计中的作用**（§8.1 对照表 + §8.4）

| UnRen 原菜单项 | 3.0 对应 | 作用 |
|---|---|---|
| 3 开控制台/开发者菜单 | `game/unren-console.rpy` | `config.developer=True` / `config.console=True`，游戏内开控制台 |
| 4 快速存读档 F5/F9 | `game/unren-quick.rpy` | 热键快速存/读档 |
| 5 强制跳过未读文本 | `game/unren-skip.rpy` | `skip_unseen`/`allow_skipping`/`fast_skipping` + TAB/CTRL 快进 |
| 6 强制回滚（滚轮） | `game/unren-rollback.rpy` | 滚轮/PAGEUP 回滚，上限 256，解除 `block_rollback` |

§8.4 三条硬约束：**修改游戏行为、与翻译无关**；**默认不启用**、不随「全部」自动执行、随时可一键移除；文档须明确它们只是调试便利。

对汉化工作流的实际价值：第 5 项是**翻译迭代最常用的**——写完回 → 进游戏 → TAB 快进到改动处 → 看效果，不必每句话都点。

## C 级：体验与健壮性

### C1. 进度条在 round 事件后被永久打成 busy，百分比再也不显示

**代码定位**
- `pytran/ui.py:78-82`：`round` 事件 → `pb.setRange(0, 0)`（indeterminate 模式）；
- `pytran/ui.py:1145-1153`：`progress` 事件 → `_refresh_progress` 只 `pb.setValue(...)`，**从不恢复 `setRange(0, 100)`**。

**现象**
翻译进入第 2 轮后，进度条永远来回滚动，看不到 §9 布局图要求的 `████████░░ 812/1000 失败 3`。Qt 中 `setRange(0,0)` 是 indeterminate，此时 `setValue()` 无效。
