# W5-UI 补充任务：术语表与提示词编辑（翻译选项卡配套）

> 任务来源：总控审核（2026-10-13）。用户实测确认翻译功能已可运行，但设计文档 §7（术语表 profile）与 §9（设置项）中「用户可编辑术语表 / 提示词」的部分**未落地**——目前 `profile.json` 只能手工编辑，违背"不需要会编程"的产品定位。

## 1. 目标

在「⚙ 设置」对话框中新增两个选项卡页，让用户无需接触 JSON 即可：

1. **术语表**：查看 / 增删改「原文 → 译名」条目；从工程一键抽取候选术语；
2. **翻译规则（提示词追加段）**：编辑一段附加到系统提示词末尾的自定义规则文本。

不动前文参考（自动机制，用户无需接触）。不动默认系统提示词主体（防用户改坏格式约束，§4.1 的 JSONL 输出规则不可破坏）。

## 2. 数据契约（已冻结，直接使用）

- `pytran.config.TermProfile`（已实现，勿改）：
  - `terms: dict[str, str]` —— 原文 → 译名
  - `exempt_english: list[str]` —— 免翻英文短语
  - `prompt_overrides: dict[str, str]` —— 目前有效键：`system_append`
  - `load(path)` / `save(path)` 已有
- profile 路径：`work_dir / "profile.json"`（`project.term_profile` 字段）
- 注入点已通：`protocol.build_system_prompt(profile)` 自动把 `terms` 与 `system_append` 注入每次请求；**翻译运行中修改不生效，下次运行生效**（对话框需提示此点）。
- 豁免短语 `exempt_english` 影响 §5.1 白名单（"含英文"判定）。

## 3. 交互设计

### 3.1 入口

「⚙ 设置」对话框顶部加两个按钮（或改为 QTabWidget 三页：常规 / 术语表 / 翻译规则）。推荐 Tab 方案：

```
┌─ 设置 ────────────────────────────────────────┐
│ [常规] [术语表] [翻译规则]                      │  ← QTabWidget
├───────────────────────────────────────────────┤
│ （术语表页布局如下）                            │
│ [从工程抽取候选…] [添加行] [删除选中]            │
│ ┌──────────────┬──────────────┐               │
│ │ 原文          │ 译名          │  ← QTableWidget 2 列
│ │ Ian           │ 伊恩          │               │
│ │ Stalkfap      │（译名留空=按原文保留）│          │
│ └──────────────┴──────────────┘               │
│ ☑ 命中术语的英文不判为"含英文"（白名单）          │
│ 免翻英文短语（每行一个）：                       │
│ ┌───────────────────────────┐                 │
│ │ Stalkfap                  │                 │
│ └───────────────────────────┘                 │
│                              [保存] [取消]     │
└───────────────────────────────────────────────┘
```

### 3.2 术语表页行为

| 控件 | 行为 |
|---|---|
| 表格 | 2 列（原文/译名），可编辑；按原文排序显示；原文重复时保存时合并（后值覆盖）并提示 |
| 添加行 | 空行追加到末尾，焦点进入新行 |
| 删除选中 | 删除勾选/选中行（支持多选） |
| 从工程抽取候选 | 扫描 `project.segments` 的 `source`，抽取候选术语（算法见 §4），弹**候选对话框**：左列候选词 + 出现次数，用户逐条填译名或忽略；确定后并入表格 |
| 保存 | 写回 `profile.json`（`TermProfile.save`）；**译名为空且原文含英文**的条目自动进 `exempt_english`（即"按原文保留"语义），弹窗汇总保存结果 |
| 翻译中修改 | 保存后弹提示「术语表将在下次翻译时生效」——不做热更新（运行中改会同批不一致） |

### 3.3 翻译规则页行为

- 一个 `QPlainTextEdit`，内容绑定 `prompt_overrides["system_append"]`；
- 顶部灰字说明：「这里的文字会追加在系统提示词末尾。用于补充风格/人名/格式要求。不要试图修改输出格式规则（JSONL），那由程序保证。」
- 保存即写入 profile.json，同页提示"下次翻译生效"。

## 4. 从工程抽取候选术语的算法（terms.py 已有雏形则复用，否则按此实现）

```
输入：project.segments（全部 source）
1. 频率统计：
   - 对 kind="strings" 的段：source 本身多为角色名/短语 → 全部计入
   - 对 kind="dialogue" 的段：抽取 1~3 词的连续大写开头词组（专名候选），
     计出现次数；排除句首普通词（启发式：在段中部/多段出现 ≥3 次才入选）
2. 过滤：
   - 已在 profile.terms 中 → 跳过
   - 命中 exempt_english → 跳过
   - 纯数字/单字母 → 跳过
3. 排序：出现次数降序，取前 50
4. 输出候选对话框：候选词 | 出现次数 | [译名输入框] | [忽略]
   - 用户填了译名的并入 terms；标记忽略的本次不再提示
```
