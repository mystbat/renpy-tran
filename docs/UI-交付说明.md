## 一、本次改动概述

### 1.【选择目录】页（Page 0）
- 增加**文件体检状态横幅**（Banner），直观提示当前目录状态：
  - 纯源码游戏：`✅ 检测到 N 个 .rpy 源码脚本！已就绪，请点击下一步「导入」进行解析。`
  - 封包游戏：`⚠️ 发现 N 个 RPA 归档包 / M 个 rpyc 字节码（游戏处于封包状态），请先点击下方「解包+反编译」！`
- 增加**文件扫描清单树（`QTreeWidget`）**：列出所选目录下所有 `*.rpa`（红标需解包）、`*.rpyc`（橙标需反编译）、`*.rpy`（绿标就绪源码）。
- 保留 `[选择游戏目录]`、`[选择单个 .rpy]`、`[解包+反编译]` 按钮。

### 2.【导入】页（Page 1）
- 增加**待导入脚本清单（带复选框的 `QTreeWidget`）**：展示相对路径、文件大小、导入状态（绿色「已导入」/ 灰色「未导入」）。
- 增加精细化导入控制：`[全选]`、`[全不选]`、`[导入勾选的脚本]`（分批/按需导入）、`[全部导入]`。
- 底部摘要标签常驻显示发现脚本数、已解析段落数、未译数与跳过数。

### 3.【审校】页（Page 3）—— 本轮新增
- 新增**筛选下拉框**（`QComboBox`）：全部 / 待翻译 / 已翻译 / 失败 / 保留原文 / 已审校。
  选项列表由 `UiState.REVIEW_FILTERS` 驱动，杜绝两处清单漂移。
- 新增**条目计数标签**：实时显示「当前筛选 N 条，已渲染 M 条，正在审校第 K 条」。
- 新增**分页渲染**：单批上限 `REVIEW_PAGE_SIZE = 1000`，`[显示更多]` 按批追加；
  渲染完即自动禁用该按钮，并在尾部给出不可选中的灰色提示行。

### 4.【选择目录】页的解包进度条（用户实测反馈）
此前 `unpack_progress` 事件写到了**翻译页的进度条**上——用户点了「解包+反编译」后，
进度被藏进【翻译】选项卡里，必须切页才能看到。本轮修复：
- 【选择目录】页新增**解包专用进度条 + 状态标签**（在「解包+反编译」按钮正下方）；
- `unpack_progress` 事件改写解包专用条，**不再与翻译进度条混用**；
- 解包前显示「准备解包……」；解包阶段按 RPA 逐文件比例前进；
  反编译阶段无逐步进度 → 显示 busy（来回滚动）指示；
- 完成态显示汇总（`完成：解包 N 个文件，反编译 M 个 .rpy`），失败显示失败原因。

### 5. 其余页面
【翻译】、【导出写回】保持独立页面容器；各选项卡可自由切换，操作按钮按工程状态实时置灰保护。

## 二、疑难修复：大工程启动假死（用户实测反馈）

### 现象
用户在含 **135,507 个段落**的真实工程下运行 `运行.bat`，窗口长时间无响应，最终以 Ctrl+C 中断：

```
File "pytran/ui.py", line 872, in _refresh_review
    lb.addItem(witem)
KeyboardInterrupt
```

### 根因与实测证据
纯 Python 计算并非瓶颈，**瓶颈是一次性创建 13.5 万个 Qt 列表条目**。离屏实测数据：

| 环节 | 旧实现 | 新实现 |
|---|---|---|
| `project.json` 载入（135,507 段） | 1.45 s | 1.45 s（未改动） |
| `review_items()` 纯逻辑 | 0.21 s | 0.21 s |
| `QListWidget` 填充 1,000 条 | — | **0.03 s** |
| `QListWidget` 填充 135,507 条 | **11.13 s** | 不再发生 |
| `run()` 构建窗口耗时 | 约 11 s+（假死） | **0.34 s** |

### 修复
1. **启动时不预填审校列表**：`_refresh_all()` 仅在当前处于审校页时才刷新列表；进入审校页（`_on_step(3)`）时才加载。
2. **分批渲染 + 显示更多**：单批 1000 条，用户可控追加。
3. **尾部提示行设为 `NoItemFlags`**：不可选中、不可导航，避免污染审校游标；
   新增 `_displayed_review_rows()` 让 `J/K` 导航永不落到提示行。
4. **游标收敛**：筛选后条目变少时，`_review_index` 自动收回到已渲染范围内。

> 实测（真实 135,507 段工程，offscreen）：`全部` → 渲染 1000/135507；
> `待翻译` → 135505（正确排除 2 条 SKIPPED）；其余筛选为 0（该工程尚未翻译）；
> 点「显示更多」→ 条目数按批增加。

## 五、已知技术债（建议后续单独排期）

1. `ui.py` 直接读写 `UiState._review_index`（私有属性）。这是本次修复前既有的做法
   （`_on_list_select` 已如此），本次沿用未扩大。建议后续在 `ui_state.py` 增加
   公开的 `set_index()` / `index` 存取器，再统一收口。
2. `_refresh_review()` 会调用 `review_items()` 构造全量 `ReviewItem` 列表（十万级约 0.2 s），
   且 `_refresh_editor()` 会再次调用 `current_review()` 重复一次。单次交互约 0.4 s，可接受；
   若后续需要更顺滑，可在 `UiState` 侧缓存过滤结果。
