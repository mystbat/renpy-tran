# ADR-0006：申报率异常闸改为「单批最小样本量 + 项目级累计双闸」

- 日期：2026-10-09
- 状态：已接受
- 影响范围：W2 protocol（§5.4 护栏 4）、W3 engine（降级模式入口）

## 背景

原 §5.4 护栏 4 只设一道比例闸：批次申报率 > `keep_declare_rate_limit`（默认 15%）
即整批降级重译并告警。但申报提示 **只在重试轮的小请求注入**（几行、最多约 5 行），
而 15% 阈值是按正常批（数十行）标定的——小批次里任意一次申报都轻易越阈：

- 3 行申报 1 行 = 33% > 15%，已被判降级；
- 更极端的「单行申报」（人名/拟声词等本就该保留的行）直接 100% 越阈。

结果是：**任何一次合法申报都会触发整批降级，申报机制事实上被废掉**，与启用
申报的初衷（收敛 target==source 歧义）自相矛盾。原始设计文档确实写过「降级」
（设计文档 §5.4 G4、ADR-0002 决策第 4 条、设计文档风险表），但单批口径的最小
样本量缺失，导致该闸在不该触发的小批次上误伤。

## 决策

护栏 4 由单闸改为 **双闸**：

### 单批闸（批次口径）
- 仅当 **批内样本 `len(kept_rows) >= KEEP_DECLARE_MIN_BATCH`（默认 5）** 且
  **申报率 `batch_declared / batch_rows > keep_declare_rate_limit`** 时，才整批
  降级为普通译文并重译、发 `alert`；
- 批内样本 < 5 行的批次 **不降级**，申报照常进入护栏 1/2 逐条人工裁定；
- 分母取本批 **实际返回且被请求** 的行数（`kept_rows`）：测的是「模型对已产出
  内容的偷懒比例」，返回行数即其声称完成的工作量；用请求行数做分母时，少返回
  （缺行）反而稀释申报率，等于奖励少答。缺行由 §V1 单独处理，不重复惩罚。

### 累计闸（项目级口径）
- 新增 `KeepDeclareAccumulator`：每次解析后调用 `record(batch_rows, batch_declared)`
  累计「计入行数 `total_rows`」与「申报行数 `total_declared`」；
- 当 **累计样本 `total_rows >= KEEP_DECLARE_CUM_MIN_ROWS`（默认 20）** 且
  **累计申报率 `total_declared / total_rows > keep_declare_rate_limit`** 时，
  置不可逆的 `degrade_mode = True`，并通过 `cumulative_alert_message()` 发全局告警；
- 累计告警挂在当批 `ParseResult.cumulative_alert` 上（不逐批降级——小批次的申报
  已逐条进人工裁定），由 W3 引擎据此进入「降级模式」；
- `degrade_mode` 一旦置位 **不可逆**（即使后续批次零申报也保持），防止滥用者用
  干净批次把计数器「洗白」。

### 关键不变量
- `kept_rows` = 返回 ∩ 想要（批次率分母）；`batch_declared` = 进入护栏前的申报数
  （累计率分子）；
- 单批闸降级会清空 `pending_keep`，故累计计数用降级前定稿的 `batch_declared`。

## 为何能同时兜住两端
- **单行合法申报**（如 3 批各 1 行人名）：每批都 < 5 行 → 单批闸全部放过，合法；
- **系统性滥用**（每批都申报一大半，但每批都 < 5 行）：单批口径逃得掉，但累计
  样本达 20 且累计率 > 15% → 累计闸触发，进入降级模式并告警。

## 后果
- W2 `protocol.py`：常量 `KEEP_DECLARE_MIN_BATCH=5`、`KEEP_DECLARE_CUM_MIN_ROWS=20`；
  新增 `KeepDeclareAccumulator` 与 `ParseResult.cumulative_alert`；`parse_response`
  新增 `accumulator` 入参；
- W3 engine：持有 `KeepDeclareAccumulator` 实例，逐次传入 `parse_response`，据
  `degrade_mode` 进入降级模式（W3 实现范围）；
- 冻结的 `config.py` 未改动；阈值/下限均通过常量与 `parse_response` 入参暴露，
  未引入新配置字段（与「config 冻结」约束一致）。

- `test_guardrail_4_accumulator_irreversible`（降级模式不可逆）。
