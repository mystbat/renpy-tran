# ADR-0011：选项卡自由导航（放弃顶部步骤条的不可用置灰）

- 日期：2026-10-19
- 状态：已接受
- 影响范围：`pytran/ui.py`（`_refresh_steps` / `_highlight_active_step`）、`pytran/ui_state.py`（`control_enabled` 保留但仅用于页内按钮）、设计文档 §9

## 背景

设计文档 §9 的布局图把顶部五个步骤按钮标注为「← 不可用置灰」，并配文字
「状态驱动置灰：无游戏目录时解包/写回灰；无 segments 时翻译灰；
无 translated 时导出灰」。

实现在 `task/UI` 期间改成了**全部选项卡可自由点击切换**
（`_refresh_steps` 里 `setEnabled(True)` 全放开），并把置灰收敛到**页内按钮**
（`btn_unpack` / `btn_writeback` / `btn_translate` / `btn_retry` /
`btn_export_csv`，仍由 `UiState.control_enabled` 驱动）。

这个偏离只写进了 `docs/UI-交付说明.md` §1.5 与用户实测清单第 10 项，
**没有回写设计文档、也没有记 ADR**，构成文档与实现的单向漂移。
用户 2026-10-19 确认：以自由导航为准，修订设计文档。

## 决策

1. **顶部五个步骤选项卡永不置灰**，任何时刻都可点击切换。
2. 置灰规则只作用于**页内操作按钮**，仍由 `UiState.control_enabled` /
   `all_controls()` 单一真相源驱动：
   - 无 `game_root`（纯文件模式）→「解包+反编译」「事务化写回」「辅助补丁区」灰；
   - 无 segments →「开始自动翻译」灰；
   - 无 translated/reviewed →「导出写回」相关灰；
   - 无 FAILED 行 →「重试失败项」灰。
3. `_on_step(idx)` 切页时对需要数据的页（审校页）做懒加载，
   避免十万级工程启动即假死（`docs/UI-交付说明.md` §2）。

## 理由

- **自由导航对大工程更友好**：十万级段落的工程里，用户常需要跳回「选择目录」
  看扫描清单、或跳去「导出写回」，被置灰的选项卡会把这些查看动作也挡掉。
  查看不需要前置条件，只有**执行操作**才需要。
- **置灰的本来目的（防止误操作产生坏数据）由页内按钮置灰完整覆盖**：
  真正有破坏性或需要前置数据的动作都在页内，且都有明确的空态提示
  （如「工程为空：请先完成选择目录和导入」）。
- 用户实测清单第 10 项（「五个步骤选项卡均可随时点击切换」）已按此验收通过，
  改回置灰会造成已验收行为回退。

## 后果

**正面**
- 十万级工程下查看各页信息不受阻；
- 置灰规则收敛到一处（`UiState`），GUI 与状态层的判据不再分叉。

**负面 / 需注意**
- 设计文档 §9 的布局图注释与「状态驱动置灰」段已同步修订（本次一并改），
  后续实现者以修订后的文档为准；
- `UiState.control_enabled("review")` 目前**未被 UI 使用**（审校页本身不置灰，
  只在其内部对空数据给出「当前筛选下没有条目」提示）。保留该方法是为将来
  若需要页级置灰时可直接启用，不构成死代码——但若长期不用，应在
  `ui_state.py` 标注「预留，当前未接线」。
