# ADR-0003：轮数硬上限为无条件终止线

- 日期：2026-10-09
- 状态：已接受
- 影响范围：W3 engine（§5.3）

## 背景

闭环重译的终止保障共有三层：检测层放行（消除误报不收敛）、定点/循环状态哈希（消除盲试循环）、
轮数硬上限。需要明确轮数上限的角色，避免被理解为「唯一保障」而在检测层正常时过早截停。

## 决策

`round_budget_cap = 5` 写死为代码常量，config 不得超过（`Config.effective_max_retry_rounds()` 钳制）。
判定顺序中**排在最前**：第 5 轮一到，剩余行立即强制 `failed`（原因 `round_budget`），
即使定点/循环检测未触发。正常情况它很少触发（检测先收敛），是绝对兜底而非主要机制。

## 理由

- 即使前两层因 bug 或意外失效，流程也必然结束——烧 token 风险有硬上界；
- 排在最前使其语义简单（预算线），不与状态机逻辑耦合。

## 后果

- W3 的引擎状态机每轮开始先查轮数；
- `test_e2e_mock` 必须包含「永远随机错 → round_budget 收敛」用例。
