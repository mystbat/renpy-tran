# ADR-0006：申报率闸的双口径修订（最小样本量 + 项目级累计闸）

- 日期：2026-10-09
- 状态：已接受（替代 ADR-0002 中护栏 4 的单批口径）
- 影响范围：W2 validators/protocol（§5.4）、W3 engine、config.py 语义

## 背景

W2 实现会话反馈：ADR-0002 护栏 4 的「单批申报率 >15% 即整批降级」在真实调用口径下自相矛盾——
申报只出现在重试轮的**小批次**（几行），15% 按 30 行大块标定。3 行申报 1 行 = 33% 即触发降级，
任何申报都无法存活，护栏 1/2/3（keep_declared 状态、一致性约束、归一化）成为死代码。
阈值本身无疑义（抓系统性滥用），错在**分母口径未定义**。

## 决策

申报率闸改为双口径：

1. **单批闸**：申报率 > `keep_declare_rate_limit` **且批内样本 ≥ `keep_declare_min_batch`（默认 5）**
   → 该批申报降级为 UNTRANSLATED 重译（原有行为）；
2. **小批次累计闸**：样本 <5 的批次不降级，逐次计入项目级累计计数器；
   累计样本 ≥ `keep_declare_min_total`（默认 20）且累计申报率 > 阈值
   → 全局告警 + 进入降级模式（此后所有申报一律降级，直至人工复核/更换模型）。

## 理由

- 护栏目的（ADR-0002）是抓「模型系统性用申报逃翻译」——那种行为在任一口径下都会暴露；
- 小批次里 1~2 行申报是合理常态（人名行、拟声行集中出现在重试包里），
  单批硬闸在小样本下统计上无意义（n=3 时任何一票都超 15%）；
- 累计闸保证「每批只申报 1 行但每批都申报」的渐进滥用仍被捕获；
- 两个新参数进 config，语义变更不改字段名，W2 的 `keep_declare_rate_limit` 保留原值。

## 后果

- W2：downgrade 判定需加 `len(batch) >= keep_declare_min_batch` 条件；累计计数器由引擎（W3）持有并传入；
- W3：Engine 维护 `declared_total/declared_kept` 计数，超累计阈置降级模式标志；
- config.py（契约）：新增 `keep_declare_min_batch=5`、`keep_declare_min_total=20` 两个字段——
  属契约变更，按拆分文档流程由总控统一执行（本次已一并修改）；
- `test_validators`/`test_protocol` 需补：n<5 不降级、n≥5 且超率降级、累计超阈进入降级模式三类用例。
- 流程教训（2026-10-09）：本 ADR 与 W1 的 fixtures 例外 ADR 同时采用了 0006 号，发生撞号——
  编号自此由总控统一登记分配（见 adr/README.md），fixtures 例外已改号为 ADR-0007。
