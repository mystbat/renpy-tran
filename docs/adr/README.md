# 架构决策记录（ADR）

每个**架构级**设计决策一个文件，命名 `ADR-<nnnn>-<标题>.md`，编号从 0001 递增，永不复用。
任务级（模块内部）取舍**不建 ADR**，写入交付说明并加 `# DECISION(§…)` 代码注释即可。

## 何时写 ADR

满足任一条：
- 影响跨模块接口或数据格式；
- 影响外部行为（协议、文件格式、游戏目录操作）；
- 拒绝了某个看起来合理的替代方案（否则后人会反复重新提出它）。

## 模板

```markdown
# ADR-<nnnn>：<标题>

- 日期：
- 状态：提议 | 已接受 | 已否决 | 已替代（被 ADR-xxxx）
- 影响范围：（模块/设计章节）

## 背景
为什么需要做这个决策（一两句 + 引用设计文档章节）。

## 决策
做了什么。

## 理由
为什么这样而不是那样（关键取舍）。

## 后果
正面 / 负面 / 需要后续注意的事项。
```
