# FEATURE(clear-project)：导入页新增「清空工程」按钮

- 日期：2026-10-20
- 触发：用户反馈「现在的导入没法清空或反导入」——导入只能整体覆盖，
  换游戏目录才会清空；重新导入（应用新解析逻辑修复，如
  BUGFIX-unrpyc-translated）前无干净起点。
- 状态：✅ 已实现（377 全量用例通过，新增 5 用例）

---

## 1. 功能

导入页操作栏新增 **「清空工程」** 按钮（位于「全部导入」右侧）：

- 清空 `segments` / `files`，`project.json` 立即归零落盘；
- **保留** `game_root`（游戏目录）与 `profile.json`（术语表）——
  同一游戏重新「导入」即按当前解析逻辑重建工程；
- 清空后回到「导入」步骤；翻译/审校/导出按钮随 `has_segments` /
  `has_translated` 自动置灰，解包/写回仍可用（game_root 在）。

## 2. 防误触

- 有已译/已审校记录时确认框**明示数量**（如「将删除 674 条段落
  （含 673 条已译/已审校）」）；
- 用户选「No」→ 不做任何改动；
- 空工程点击 → 仅提示「工程已经是空的」，不弹确认。

## 3. 与既有清空路径的关系

| 路径 | 清空范围 | 触发方式 |
|---|---|---|
| 本按钮 | segments + files，保留 game_root/术语表 | 手动、可控、可确认 |
| 换游戏目录 | 全部（含术语表，§7.2 防串游戏） | 自动 |
| 换单文件 | 全部 | 自动 |

本按钮填补「同目录重新导入」场景：只想用新解析逻辑重建、不想重选
目录或丢术语表。

## 4. 测试（tests/test_ui_clear_project.py，5 用例）

- 按钮存在；
- 清空后 segments/files 归零、game_root 保留、步骤回到导入页、
  project.json 落盘可回读；
- 确认框选「No」→ 不清空；
- 空工程重复点击不抛；
- 清空后控件置灰符合 §9 规则（翻译/审校/导出灰，导入/解包可用）。

回归：`python -m pytest tests -p no:cacheprovider` → **377 passed**。

## 5. 用户操作指引

导入页 → 点「清空工程」→ 确认 → 重新勾选并导入。适用于：
应用了解析修复后重建工程；导入选错文件想重来；或想把已译记录清掉
从零翻译。
