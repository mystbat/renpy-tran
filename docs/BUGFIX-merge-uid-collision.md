## 2. 根因

「合并导回」（`ui._merge_import`）走 `backfill.match_translations`，
其**第一级匹配是 uid 精确**。而 uid 是「**单次导入内的段序号**」——
`build_project` 每次导入都从 1 重编。于是：

1. 合并导入用新文件 `build_project` → uid 1..N 重编；
2. 旧工程已译段构造 `TranslationRow(uid=旧uid)`；
3. uid 精确命中新工程**同号的完全不同的段** → 旧译文写进去、置 REVIEWED；
4. 用户写回 → 所有文件的译文按错位 uid 配回文件 → 全面污染。

特征码（label）/相似度两级本是正确的跨导入主键，却被 uid 级抢先命中。

## 3. 修复

1. **`match_translations` 的 uid 级匹配默认关闭**（新增
   `use_uid_matching=False` 参数）；跨导入禁用，同会话内 CSV 回填
   （`import_csv` 先用 `by_uid` 直配，未命中才走兜底）可显式开启——
   两调用方均无需改动即获得正确语义。
2. **`_merge_import` 增加 `(文件, 原文)` 精确对位前置层**：同一文件
   的同一句原文，译文直接沿用（最可靠键）；特征码/相似度仅对未命中
   行兜底；日志区分「精确沿用 / 兜底命中 / 遗留未匹配」。
