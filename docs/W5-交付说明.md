## 一、本次做了什么

W5 是「壳与人工通道」：把底层解析（W1）、引擎（W2）、游戏解包（W4b）等已就绪的能力，封装成**可被用户操作的两类界面**——命令行与图形界面，并补齐「人工审校/批量接受」这一环。

交付四块：

1. **导出层 `ExporterImpl`**（§6.3–§6.5）
   把翻译结果导成 CSV 供人工编辑、再回灌；导出 rpy 前按熔断规则（未译/失败/标记检查/匹配率）拦截；人工批量接受前先快照到 journal，使操作可撤销，并可选地收集被保留的原句到 `exempt_english`。

2. **UI 状态机 `UiState`**（§9 纯逻辑）
   把「哪一步、哪些按钮可用、进度多少、当前审校到第几条」全部收敛到一个可单测的对象里，不依赖 Tk。这是 GUI 不会写乱的关键——所有置灰/导航规则都在这里集中实现与测试。

3. **命令行壳 `cli.py`**（§8.3/§13/§15）
   四个子命令：`translate`（纯文件）、`game`（游戏目录一键）、`auto`（全流程）、`auto-batch`（批处理）。落地了设计里的三道重要防线：L2 全自动必须显式 `--yes`；启动前做成本 dry-run，超 `--budget-max` 直接拒绝；所有副作用通过注入依赖完成，便于单测用替身。

4. **图形视图 `ui.py`**（§9 薄壳）
   只做「状态→控件」「控件→状态」的渲染与转发。严格遵守 §9 硬规则——**后台线程只发事件，不碰任何 Tk 对象**；Tk 调用全部集中在主线程，通过 `queue` + `root.after` 把后台事件安全地投递回来。

## 二、设计意图如何落到代码

| 设计诉求 | 代码落点 | 为什么这样写 |
|---|---|---|
| §9「后台线程只发事件」 | `PytranApp.on_event` 仅 `queue.put`；`_drain_events` 在主线程消费 | 跨线程改 Tk 控件会崩溃；事件桥是唯一安全通道 |
| §9「三条置灰规则」 | `UiState.control_enabled`/`all_controls` | 规则集中在纯对象，GUI 与测试共用同一真相源 |
| §15.1「L2 必须 `--yes`」 | `check_level_policy` 抛 `SystemExit(2)` | 策略门在流程最前，避免任何副作用先发生 |
| §15.3「成本闸」 | `estimate_token_budget` + `within_budget` | dry-run 估算不翻译，超预算启动即拒，零浪费 |
| §6.5「批量接受可撤销」 | `bulk_accept` 先 `journal.begin/record` 再改状态 | 先快照后应用，异常可 `rollback`/`bulk_undo` |
| §6.4「CSV 不静默覆盖」 | `import_csv` 按 uid 主键回灌 + §6.2 兜底 | 缺失 uid 不整体覆盖，避免误清空译文 |

## 三、测试策略

- **纯逻辑优先**：`exporter` 与 `ui_state` 不依赖任何外部服务/显示栈，用内存替身即可覆盖 §6.3/§6.4/§6.5/§9 的全部规则。
- **CLI 用替身注入**：`FakeProvider`/`FakeEngine`/`FakeUnren`/`FakeExporter` 注入 `CliDeps`，把 L2 授权、成本闸、L0/L1 vs L2 写回分支、失败隔离都变成确定可测的断言。
- **GUI 只测无头部分**：`run()` 需显示标 `pragma: no cover`；事件桥、延迟 import、无 root 空转由 `test_ui_smoke` 覆盖。

结果：**41 专属用例 + 224 全量用例全绿**。
