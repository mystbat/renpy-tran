## 一、本次做了什么

W5 是「壳与人工通道」：把底层解析（W1）、引擎（W2）、游戏解包（W4b）等已就绪的能力，封装成**可被用户操作的两类界面**——命令行与图形界面，并补齐「人工审校/批量接受」这一环。

交付四块：

1. **导出层 `ExporterImpl`**（§6.3–§6.5）
   把翻译结果导成 CSV 供人工编辑、再回灌；导出 rpy 前按熔断规则（未译/失败/标记检查/匹配率）拦截；人工批量接受前先快照到 journal，使操作可撤销，并可选地收集被保留的原句到 `exempt_english`。

2. **UI 状态机 `UiState`**（§9 纯逻辑）
   把「哪一步、哪些按钮可用、进度多少、当前审校到第几条」全部收敛到一个可单测的对象里，不依赖 Tk。所有置灰/导航规则集中实现与测试。

3. **命令行壳 `cli.py`**（§8.3/§13/§15）
   子命令 `translate`/`game`/`auto`/`auto-batch`；L0–L2 分级、`--yes`、`--budget-max` 成本闸、dry-run；依赖注入解耦。`build_deps(allow_missing_provider=True)` 支撑 §9 未配置模式。

4. **图形视图 `ui.py`**（§9 薄壳 + L483 设置对话框）
   只做「状态→控件」「控件→状态」的渲染与转发，严格遵守 §9 硬规则——**后台线程只发事件**（`on_event` 仅 `queue.put`，`_drain_events` 主线程消费）。**本次收尾补全 §9 L483 设置对话框**：原交付漏了「模型参数(fallback_model/max_tokens/temperature/top_p)、并发数、预算上限」，现已全部覆盖，并接入 §8.5 SDK 实时校验/版本探测。

## 二、设计意图如何落到代码

| 设计诉求 | 代码落点 | 为什么这样写 |
|---|---|---|
| §9「后台线程只发事件」 | `on_event` 仅 `queue.put`；`_drain_events` 主线程消费 | 跨线程改 Tk 控件会崩溃；事件桥是唯一安全通道 |
| §9(L483)「设置项齐全」 | `_open_settings` 覆盖 11 项字段（含模型参数/并发/预算） | 全部复用冻结 `Config` 既有字段，无需契约变更 |
| §8.5「SDK 实时校验」 | `_validate_sdk` 复用 `SdkBridgeImpl.probe` | 不重复实现版本探测（py2→7.x / py3→8.x），复用既有桥 |
| §9 未配置模式 | `_current_config` 用 `allow_missing_provider=True`；填 Key 后 `_build_default_deps(api_key=)` 注入运行时 Key | 空 Key 不再急切构造 `OpenAIProvider` 触发 `OpenAIError`；ADR-0004 保证 Key 不入文件 |
| §15.1「L2 必须 `--yes`」 | `check_level_policy` 抛 `SystemExit(2)` | 策略门在流程最前，避免副作用先发生 |
| §15.3「成本闸」 | `estimate_token_budget` + `within_budget` | dry-run 估算不翻译，超预算启动即拒 |
| §6.5「批量接受可撤销」 | `bulk_accept` 先 `journal.begin/record` 再改状态 | 先快照后应用，异常可 `rollback`/`bulk_undo` |
| §6.4「CSV 不静默覆盖」 | `import_csv` 按 uid 主键回灌 + §6.2 兜底 | 缺失 uid 不整体覆盖，避免误清空译文 |

## 四、需要总控裁决的偏差（已规避冻结契约）

本会话**未修改**任何冻结文件（`models.py`/`config.py`/`interfaces.py`）。

1. **`Exporter` 协议扩展**（契约变更建议，ADR 待分配编号）
   已以可选参数扩展临时落地（`export_rpy_forced` / `write_back_project` / `bulk_accept(add_exempt=)`），向后兼容。建议总控在 `interfaces.py` 正式扩充并补 ADR。

2. **§9 L483 设置对话框（本收尾补全，契约零改动）**
   原交付的 `ui.py` 设置对话框漏了「模型参数/并发数/预算上限」。本次在不改冻结 `Config` 前提下补全 6 个字段；ADR-0004 仍保证 `api_key` 不落盘；数值字段经 `_coerce_setting` 收敛为 `int/float` 写入对应 section。复用既有 `Config` 全部字段，无需契约变更。

3. **§9 未配置模式 provider 修复（本收尾）**
   原 `_current_config` 空 Key 时急切构造 `OpenAIProvider` 会抛 `OpenAIError`。本收尾改用 `allow_missing_provider=True`，并在填 Key 保存时注入**运行时 Key** 重建依赖（因 Key 不入文件，回读空文件会再次触发 OpenAIError）。属缺陷修复，未改冻结契约。

4. **`include_errors` 通道（W3 遗留）**
   引擎内层该标志仍为 noop；壳层未开启。W3 总控裁决「留待 W5 契约扩展」，本次未突破，属已知缺口。

5. **解包/反编译目录**
   遵循 W4b 备注，反编译输出落 `logs/`（由 `UnrenImpl` 保证）。

## 一、本次做了什么（对照任务书 §2）

1. **新增状态 `KEEP_ORIGINAL`**（§2.1，契约变更，已获任务书 §2.1 预先授权）
   - `models.py`：`SegmentStatus` 新增 `KEEP_ORIGINAL = "keep_original"`；
     `ProjectStats` 新增 `keep_original: int = 0`；`to_dict`/`from_dict` 往返。
   - `ProjectStats.from_segments` 用动态 `hasattr/setattr`，新状态自动计入统计，无遗漏。

2. **审校页「保留原文」操作**（§2.2）
   - `ui_state.py`：新增 `keep_original_current()` —— 置 `status=KEEP_ORIGINAL`、
     `target=source`、`error=None`；无当前审校项时返回 `False`（不抛异常）。
   - `REVIEW_FILTERS` 追加 `"keep_original"`（与 `keep_declared` 并列）。
   - `ui.py`：审校按钮行加 `o 保留原文`（`btn_keep`→`_on_keep`）；`REVIEW_FILTER_LABELS`
     两键均映射「保留原文」（按用户「不区分」裁定，二者同标签，但 filter 键独立）；
     列表与预览面板对 `KEEP_ORIGINAL` 用琥珀色 + `[保留原文]` 标识（同 `KEEP_DECLARED`）。
   - **快捷键冲突处理**：任务书 §2.2 建议 `k`，但 master 的 `ui.py` 早已将 `j/k` 用于
     列表上下导航（设计既定「j/k 上下」）。为最小改动、不破坏导航，**改绑 `o`（Original）**，
     按钮标签同步为「o 保留原文」。

3. **重试范围修正（核心，§2.3）**
   - `engine._build_queue`：队列口径由 `PENDING/FAILED/KEEP_DECLARED` 收紧为
     **`PENDING/FAILED`**；`KEEP_DECLARED` 与 `KEEP_ORIGINAL` 均不进队列（根因修复）。
   - `ui._translatable_uids`：同步收紧为 `PENDING/FAILED`（三处入口——全量翻译 / 重试失败 / 试译
     ——共用该集合与 `_build_queue`，口径一致）。

4. **写回语义（§2.4）**
   - `exporter.bulk_accept`：循环置 REVIEWED 时**跳过 `KEEP_ORIGINAL`**（不被强制接受）；
     `KEEP_DECLARED` 仍一并接受。
   - 写回 `regenerate` 已有「有 target 则替换、无则逐字节保留」逻辑；`keep_original_current()`
     显式令 `target=source`，故写回 new 行 = 原文（内容正确且语义清晰）。无需特殊分支。
   - `progress()` 仅把 `TRANSLATED/REVIEWED` 计入 `done`，`KEEP_ORIGINAL` 不计入完成数（符合 §2.4 表意）。
