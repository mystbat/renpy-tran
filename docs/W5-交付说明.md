## 一、本次做了什么

W5 是「壳与人工通道」：把底层解析（W1）、引擎（W2）、游戏解包（W4b）等已就绪的能力，封装成**可被用户操作的两类界面**——命令行与图形界面，并补齐「人工审校/批量接受」这一环。

交付四块：

1. **导出层 `ExporterImpl`**（§6.3–§6.5）
   把翻译结果导成 CSV 供人工编辑、再回灌；导出 rpy 前按熔断规则（未译/失败/标记检查/匹配率）拦截；人工批量接受前先快照到 journal，使操作可撤销，并可选地收集被保留的原句到 `exempt_english`。

2. **UI 状态机 `UiState`**（§9 纯逻辑）
   把「哪一步、哪些按钮可用、进度多少、当前审校到第几条」全部收敛到一个可单测的对象里，不依赖 Tk。所有置灰/导航规则集中实现与测试。

3. **命令行壳 `cli.py`**（§8.3/§13/§15）
   子命令 `translate`/`game`/`auto`/`auto-batch`；L0–L2 分级、`--yes`、`--budget-max` 成本闸、dry-run；依赖注入解耦。`build_deps(allow_missing_provider=True)` 支撑 §9 未配置模式。

4. **图形视图 `ui.py`**（§9 薄壳 + L483 设置对话框）
   只做「状态→控件」「控件→状态」的渲染与转发，严格遵守 §9 硬规则——**后台线程只发事件**（`on_event` 仅 `queue.put`，`_drain_events` 主线程消费）。**本次收尾补全 §9 L483 设置对话框**：原交付漏了「模型参数(fallback_model/max_tokens/temperature/top_p)、并发数、预算上限」，现已全部覆盖，并接入 §8.5 SDK 实时校验/版本探测。

## 二、设计意图如何落到代码

| 设计诉求 | 代码落点 | 为什么这样写 |
|---|---|---|
| §9「后台线程只发事件」 | `on_event` 仅 `queue.put`；`_drain_events` 主线程消费 | 跨线程改 Tk 控件会崩溃；事件桥是唯一安全通道 |
| §9(L483)「设置项齐全」 | `_open_settings` 覆盖 11 项字段（含模型参数/并发/预算） | 全部复用冻结 `Config` 既有字段，无需契约变更 |
| §8.5「SDK 实时校验」 | `_validate_sdk` 复用 `SdkBridgeImpl.probe` | 不重复实现版本探测（py2→7.x / py3→8.x），复用既有桥 |
| §9 未配置模式 | `_current_config` 用 `allow_missing_provider=True`；填 Key 后 `_build_default_deps(api_key=)` 注入运行时 Key | 空 Key 不再急切构造 `OpenAIProvider` 触发 `OpenAIError`；ADR-0004 保证 Key 不入文件 |
| §15.1「L2 必须 `--yes`」 | `check_level_policy` 抛 `SystemExit(2)` | 策略门在流程最前，避免副作用先发生 |
| §15.3「成本闸」 | `estimate_token_budget` + `within_budget` | dry-run 估算不翻译，超预算启动即拒 |
| §6.5「批量接受可撤销」 | `bulk_accept` 先 `journal.begin/record` 再改状态 | 先快照后应用，异常可 `rollback`/`bulk_undo` |
| §6.4「CSV 不静默覆盖」 | `import_csv` 按 uid 主键回灌 + §6.2 兜底 | 缺失 uid 不整体覆盖，避免误清空译文 |
